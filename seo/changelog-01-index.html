A. Technical

T1 HTTP is served directly — no redirect to HTTPS High

Now 
$ curl -I http://blakecody.com
HTTP/1.1 200 OK          <- serves the page. No 301. No Location header.
server: GitHub.com

Google treats http:// and https:// as two separate URL sets, so the site currently exists twice. There is no HSTS, anyone landing on an http:// link sees Chrome's "Not secure", and the GoatCounter script (see K2) is loaded protocol-relative, so on those loads your analytics go over plaintext too.

Change to

GitHub repo → Settings → Pages → Enforce HTTPS (checkbox). The certificate is already provisioned, so this is a two-minute change with no code.

Verify 
$ curl -I http://blakecody.com
HTTP/1.1 301 Moved Permanently
location: https://blakecody.com/

T2 The only real content on the page is rendered client-side from a third-party API High

Now

The served HTML contains an empty container and a loading string:

<div class="state" id="state">Loading the latest…</div>
<div class="post-list" id="post-list" data-limit="3"></div>

Posts are injected by app.js → init() → loadFromSubstack(), which fetches api.rss2json.com (a public relay, with the API key hardcoded in the client-side file) and only then builds the cards. Measured: 146 words of static indexable text vs 242 words after render.

Googlebot does render JavaScript, but on a deferred second pass and within a budget — and a cross-origin API call inside that pass makes your freshest content non-deterministic to the crawler. Bing, and essentially every AI/LLM crawler, do not execute JS at all: they see "Loading the latest…" and nothing else.

Change to
  1. Prerender at build time. A GitHub Action on a cron (say every 6 hours) fetches the Substack RSS, writes the latest 3 cards into index.html and 12 into articles.html, and commits. The content is then in the served HTML for every crawler, on a static host, at zero runtime cost. app.js keeps its fetch only to refresh what is already there.
  2. Interim (10 minutes): add a <noscript> block with the three most recent post titles and links, plus the ItemList JSON-LD from T5.

Note: the hardcoded rss2json key is public in app.js and served to every visitor. That is inherent to this pattern, but it means anyone can spend your quota — another reason to move the fetch to build time, where the key can live in GitHub Actions secrets.

T4 Render-blocking third-party font CSS sits on the critical path High

Now 
<link href="https://fonts.googleapis.com/css2?family=Fraunces:ital,opsz,wght@0,9..144,400;0,9..144,600;
1,9..144,400&family=Inter:wght@400;500;600&display=swap" rel="stylesheet" />

Two families, six faces including an italic, fetched from a third party, render-blocking, in the head. In the headless render where that host was unreachable, first-contentful-paint was 12.9 seconds — the page painted nothing at all until the request gave up. In normal conditions it is fast, but it is still a single point of failure that can hold your entire first paint hostage, and it costs a DNS lookup + connection + round trip before anything appears.

Change to

Best: self-host. Download the woff2 files into /fonts/, declare them with @font-face { font-display: swap } in styles.css, and preload the two faces used above the fold:

<link rel="preload" href="/fonts/fraunces-600.woff2" as="font" type="font/woff2" crossorigin>
<link rel="preload" href="/fonts/inter-400.woff2"    as="font" type="font/woff2" crossorigin>

Minimum: keep Google Fonts but make it non-blocking, and drop the faces you do not use (the Fraunces italic and at least one Inter weight):

<link rel="preload" as="style" href="https://fonts.googleapis.com/css2?..."
      onload="this.onload=null;this.rel='stylesheet'">

display=swap is already set — that part is correct.

T6 The LCP image is invisible to the browser's preload scanner Medium

Now

The full-screen hero (hero-bg.jpg, 1600×1000, 90KB) is not referenced in the HTML or the CSS. app.js sets it as an inline style after it parses:

function setCover(url) {
  if (url && els.coverImg) els.coverImg.style.backgroundImage = `url("${url}")`;
}

So the largest element on the page cannot begin downloading until HTML parse → JS download → JS execute have all finished. That is a wholly avoidable delay on your Largest Contentful Paint.

Change to

CONFIG.coverImage is a constant ("hero-bg.jpg"), so declare it statically and let JS only override it in the "use the latest post's cover" branch:

/* styles.css */
.cover-img { background-image: url("hero-bg.jpg"); }

<!-- index.html, in <head> -->
<link rel="preload" as="image" href="hero-bg.jpg" fetchpriority="high">

T7 A six-second intro animation owns the first visit Medium

Now

buildIntro() runs a 4.6-second choreography and the overlay is removed at setTimeout(..., 6000). A full-screen element covers the page for ~6s on the first load of every browsing session — which is exactly the load a visitor arriving from Google gets.

Credit where due: it is sessionStorage-gated so it does not replay, it respects prefers-reduced-motion, and it is aria-hidden. Those are the right instincts. The problem is purely that it runs during the LCP window, doing SVG and clip-path work on the main thread while the browser should be painting content.

Change to
  • Cut the timeline to ~1.8–2.5s total (compress the 1.1s line draw and the 2s shine).
  • Start it only after the hero image has decoded, so it never competes with LCP:
    document.querySelector('.cover-img') → new Image().decode().then(startIntro)
  • Optionally show it only on direct/bookmark entries (!document.referrer), so search visitors go straight to content.

T9 Sitemap lastmod is stale and contradicted by the server Medium

Now

All five URLs claim <lastmod>2026-06-21</lastmod>. The live Last-Modified header on / is 2026-07-20. The file also uses <priority>, which Google has ignored for years.

lastmod is the one sitemap field Google does still use, and only while it trusts it. A date that is provably wrong teaches it not to.

Change to

Generate the sitemap in the same GitHub Action as T2, taking each date from the file's last git commit:

git log -1 --format=%cs -- index.html   # -> 2026-07-20

Drop <priority>. Keep 404.html excluded (correct as-is).

T11 Scripts are not deferred Low

<script src="app.js?v=23"></script> sits at the end of <body> — the classic pattern, so the parsing cost is small, but the download does not begin until the parser reaches it. Move both scripts into <head> with defer: the browser starts fetching immediately and still executes after parse, in order.

<script src="app.js?v=23" defer></script>

T12 The Substack embed iframe is not lazy Low

Rendered loading: "auto" on .sub-frame, whose src is set by JS to https://bccody.substack.com/embed. That pulls a whole third-party document during load for a signup box that lives below the fold.

<iframe class="sub-frame" title="Subscribe by email" loading="lazy" …>

Better still: set src from an IntersectionObserver when it comes within a viewport of the fold.

T14 Missing feed link, rel="me", and Bing verification Low

Add rel="me" to the Substack and App Store links so they corroborate the sameAs list in T5. And verify the site in Bing Webmaster Tools — see K5.

T13 Caching is capped at 10 minutes and you cannot change it Info

Every asset returns cache-control: max-age=600. That is GitHub Pages' fixed default — not configurable. Worth knowing that your ?v=23 cache-busting query strings are not buying you anything against a 10-minute TTL.

If repeat-visit performance ever matters, putting Cloudflare's free tier in front lets you set max-age=31536000 on hashed assets, and hands you HSTS, Brotli and image resizing at the same time.

C. Tracking & measurement

K1 GoatCounter counts pageviews and nothing else High

Now 
<script data-goatcounter="https://bccody03.goatcounter.com/count" async
        src="//gc.zgo.at/count.js"></script>

The default snippet, unmodified. A grep of app.js for goatcounter returns zero hits. You can see that the homepage got traffic. You cannot see whether a single person clicked through to Substack, tapped the App Store badge, requested the chapter, or sent a reflection. Every conversion on this site is currently unmeasured, which means you have no way to tell whether any of the other changes in this document worked.

Change to

Add a helper and five call sites. GoatCounter events are free and need no extra script:

function track(name, title) {
  if (window.goatcounter && window.goatcounter.count) {
    window.goatcounter.count({ path: name, title: title || name, event: true });
  }
}

// 1 + 2 — every outbound click, one delegated listener
document.addEventListener('click', (e) => {
  const a = e.target.closest('a'); if (!a || !a.href) return;
  if (a.href.includes('substack.com'))
    track('click-substack-' + (a.id || a.closest('.post') ? 'card' : 'other'), 'Substack click');
  if (a.href.includes('apps.apple.com')) track('click-appstore', 'App Store click');
});

// 3 — in the chapter form's success branch (app.js ~line 240)
track('chapter-request', 'Chapter 1 requested');

// 4 — in the reflect form's success branch (app.js ~line 305)
track('reflect-submit-' + (payload.category || 'none'), 'Reflection sent');

// 5 — in the init() catch block — turns T3 into an alert, not a surprise
track('feed-error', 'Substack feed failed');

Those five rows in GoatCounter are the entire business value of the site, and right now none of them exists.

Now

Change to

K4 Search Console is verified but barely used Medium

The google-site-verification meta tag is present, so the property exists. Checklist to make it useful:

  • Add a Domain property (DNS-verified) alongside the URL-prefix one. A domain property covers http, https and www in a single view — which matters a great deal given T1.
  • Submit sitemap.xml explicitly. robots.txt discovery works but is slower and gives you no error reporting.
  • Run URL Inspection → Test live URL → View rendered HTML on /. Confirm the three post cards are present and are real posts, not the samples from T3. This single test settles both T2 and T3 definitively.
  • Watch the Coverage report for /index.html appearing as a duplicate (T8).

K7 No visibility when something breaks Medium

If rss2json goes down, or the API key hits its quota, or a GitHub Pages certificate renewal fails, you find out by visiting your own site. Two free fixes:

  • The feed-error event from K1 — a GoatCounter row that spikes the moment the feed breaks.
  • An UptimeRobot check (free tier) on https://blakecody.com, 5-minute interval, email alert. It catches cert failures and DNS problems too.

K2 Protocol-relative analytics URL Low
